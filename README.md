# Бот записи для салона красоты (демо-проект)

Рабочий Telegram-бот, который заменяет администратора на приёме заявок: клиент
выбирает услугу, мастера, день и время; свободные окна считаются сами; админ
получает уведомление; за 2 часа до визита клиенту приходит напоминание.

**Кликабельное демо без установки:** `demo/index.html` — откройте в браузере.

## Что умеет

| Шаг | Что происходит |
|---|---|
| Запись | 6 нажатий: услуга → мастер → день → время → имя → телефон |
| Слоты | рабочий день 10:00–20:00, шаг 30 мин, длительность услуги учитывается |
| Пересечения | занятый слот исчезает из выбора; двойная запись отклоняется даже при гонке |
| Напоминания | за 2 часа до визита |
| Отмена | клиент отменяет сам, админ получает уведомление |
| Админ | «Новая запись» в личку + `/today` — расписание дня и сумма выручки |

## Запуск (2 минуты)

```bash
python -m venv .venv && .venv/Scripts/activate     # Windows
pip install -r requirements.txt
copy .env.example .env                              # вставить BOT_TOKEN из @BotFather
python -m bot.main
```

Токен: @BotFather → `/newbot` → скопировать строку. Свой Telegram ID для админки:
@userinfobot. Всё остальное (услуги, мастера, часы работы) правится в `bot/db.py`
и `bot/config.py`.

## Управление ботом

```bat
run.bat        :: запуск (создаст venv, если его нет)
start.ps1      :: убить все экземпляры и поднять один
stop.ps1       :: остановить
count.ps1      :: показать, сколько запущено (норма — 1 бот; на Python 3.13+ в venv
               :: видно две строки: лаунчер + сам интерпретатор, это один бот)
```

Второй экземпляр сам не запустится: `bot/main.py` берёт блокировку `bot.lock`,
и дубль выходит с сообщением «Бот уже запущен». Это защита от двойного клика по
`run.bat`, из-за которого Telegram отдаёт `TelegramConflictError`.

Первый, кто напишет боту при пустом `ADMIN_IDS`, становится админом, и его id
сам прописывается в `.env` — после перезапуска доступ сохраняется.

Лог: `bot.log`.

## Проверки

```bash
python tests/test_db.py      # логика слотов и БД
python tests/test_flow.py    # весь сценарий записи через настоящий Dispatcher, но без Telegram
```

`test_db.py` — 25 проверок: границы рабочего дня, длительность услуги, пересечения,
прошедшее время, двойная запись, отмена, напоминания, форматирование.
`test_flow.py` — прогон сценария целиком (старт → услуга → мастер → день → время →
имя → телефон → подтверждение → мои записи → отмена → админка): проверяется текст
каждого сообщения и что именно записалось в базу. Telegram подменяется фейковой
сессией, остальное настоящее.

Первый, кто напишет боту при пустом `ADMIN_IDS`, автоматически становится
администратором — так проще запускать у клиента.

## Структура

```
bot/config.py     токен, часы работы, тексты салона
bot/db.py         SQLite + вся логика слотов
bot/keyboards.py  клавиатуры и callback-фабрики
bot/handlers.py   запись, мои записи, админка
bot/main.py       запуск + цикл напоминаний
demo/index.html   кликабельное демо для показа клиенту
tests/test_db.py  проверки логики
```

## Что меняется под клиента за 10 минут

- услуги, цены, длительность — таблица `services`;
- мастера — таблица `masters`;
- часы работы и шаг слотов — `config.py`;
- название, адрес, телефон — `.env`;
- любые тексты — `handlers.py`.
